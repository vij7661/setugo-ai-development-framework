C. CRITICAL_FINDINGS
1. **Nested negative-zero canonicalization defect.** `canonicalize_json_text` does not preserve integer lexical form for values inside JSON objects/arrays. Python `json.loads` normalizes `-0` to integer `0`, and `_normalize_value` accepts it. Therefore input such as `{"n":-0}` is silently canonicalized to `{"n":0}` instead of rejecting negative zero as required by the frozen GCP rejection rule / canonicalization rules. The existing rejection vector only covers top-level `-0` in `integer_lexical` context, so the defect is not caught by the current tests. This is a real canonicalization ambiguity and can silently turn an invalid frozen-GCP input into a valid canonical form.
