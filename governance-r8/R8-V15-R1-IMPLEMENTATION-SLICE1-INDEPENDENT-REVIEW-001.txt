D. HIGH_FINDINGS
1. Candidate commit identity is not verified against repository state. `FrozenSchemaRuntime.load()` checks only the caller-supplied `candidate_sha` argument against a hardcoded constant. It does not verify that `repo_root` is at `f93ca26975ecb64f0da13779889c75b36140cdfc`, nor does it hash the repository tree. A caller can pass the correct candidate string while pointing at a different tree that happens to contain the exact frozen schema files. Schema bytes remain hash-pinned, but commit-level candidate identity pinning is weaker than the prereg language suggests.
2. TOCTOU in exact-byte checks. The loader hashes files with `_sha256_file()`, then later reopens and parses them with `_load_json()` or `path.read_bytes()`/`read_text()` without holding a file descriptor or hashing the parsed bytes. A concurrent mutation between hash verification and parse could violate the “exact bytes before use” guarantee.
3. Source-map/SPM cross-validation is incomplete. `Runtime.load()` compares only `Path(a["path"]).name` for SPM artifacts against `source_map["artifact_sources"]` keys. It does not verify full relative paths, source-ref binding per entry, or that source-map artifact references match SPM entry `source_ref_ids`. The hardcoded source-map SHA mitigates this for the frozen input, but the validator logic itself is weaker than stated.
