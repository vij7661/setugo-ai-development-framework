G. PERMANENT_INVARIANT_ASSESSMENT
1. Review grammar structural, not example-based — Partially held: the implemented parser is genuinely structural (regex on line-start tokens, not an enumerable literal list), but it only covers the legacy 8-section grammar, not this packet's own 10-section contract (F-02).
2. Single semantic owner for authority declarations — Held for the grammar it covers: duplicate/contradictory/embedded activation-authority lines fail closed (confirmed by the adversarial table tests).
3. Workflow commands executable/CLI-compatible — Held as far as tested: the invariant gate asserts `--expected-sha256`/`--expected-blob`/`--review` sit on the same shell line as the preflight invocation.
4. Semantic verification recomputes canonical results — Held: `verify_inventory` is exercised with a tamper test that flips a classification and confirms detection.
5. Evidence identity binds the complete tuple — Weakened: the tuple is bound for the Stage1/Stage2 successor lineage, but the Q14 candidate's own ledger entry is not kept in sync with its frozen identity (F-06), and freeze status itself is not a checked field (F-03).
6. Queue completeness — Weakened: presence-only check; field-accuracy drift for the reviewed task itself is possible and currently present (F-06).
7. Filesystem confinement, fixed root, descriptor-safe — Held: `read_confined_file` uses per-component `openat`-style descriptors with `O_NOFOLLOW`/`O_DIRECTORY`, and both the runtime helper and `r8_evidence_bundle_integrity.py`'s helper are exercised against a lexical parent-traversal alias in the invariant gate.
8. Deterministic packet projection from one SHA/tree — Weakened: the manifest still declares `OPEN_CONVERGENCE_NOT_FROZEN` for what is presented as a frozen tree (F-03).
9. Cross-component load-bearing equality — Held: the gate pins the exact runtime blob SHA and asserts the evidence-bundle tool imports `read_confined_file` from it.
10. Provider API request preservation — Partially held: fingerprinting and governance-only-preserves-fingerprint logic work for the tested top-level shape, but the leak check is non-recursive (F-04) and secret scrubbing is optional (F-05).
11. Mandatory reviewer evidence actually delivered — Not held in practice: the machinery exists and is unit-tested but is not wired into any real ingestion path (F-01).
12. Reviewer solutions advisory, implementer adjudicates — Held: `validate_finding_solution_contract` / `validate_solution_adjudication` correctly separate proposal from authority, and adjudication states are a closed enum.

H. API_AND_REVIEWER_DELIVERY_ASSESSMENT
Provider API request preservation is directionally sound (canonicalization, POST/field-shape validation, fingerprint diffing gated by declared change class) but has two real gaps: the anti-leak check doesn't recurse into `provider_parameters`/`messages` (F-04), and header/secret scrubbing is opt-in rather than enforced (F-05). None of the four reviewer evidence-delivery modes are actually reachable from a real workflow — the whole module is validated only by its own tests and the invariant gate's synthetic self-check (F-01). Within the module itself, `AUTHENTICATED_GITHUB_MCP_READ_ONLY` and `PLATFORM_MATERIALIZED_CONTENT` are well-specified (object ids/content hashes required, read-only enforced), `URL_ONLY` correctly can never satisfy `validate_review_delivery_request`, but `PROVIDER_URL_CONTEXT` falls short of its own documented "fetched content identity must be recorded" requirement (F-07).
