**D. Critical findings**

1. **(carried) R11-A — interpreter isolation is asserted, never verified.** `r11_trusted_external_guard.py`'s `build_pinset()` hardcodes `interpreter_contract: {isolated_mode: true, no_site: true, ignore_environment: true, ...}` into the pinset unconditionally. I additionally confirmed this in `v24_v6_external_execution_binding.py::validate_external_execution_pinset`, which checks `interpreter.get(key) is not True` — i.e., it checks the *pinset says* True, never `sys.flags.isolated`/`sys.flags.no_site` on the actually-running process. Nowhere in the ~30 files I read does anything call `sys.flags`. **Bypass:** invoke the runner without `-I -S -E`; every consumer of the pinset still sees `isolated_mode: true`.
2. **(carried) R11-A — concrete forgeable outcome.** A pinned "dependency" module executing `unittest.TestResult.wasSuccessful = lambda self: True` at import time (triggered automatically since every pinned test file does `from v24_v6_... import ...`) silently forges the runner's exit code. Byte-pinning proves identity, not behavior; nothing sandboxes execution.
3. **(new) Q/P — adversarial-check attestation has no evidence binding.** `v24_v6_integrated_successor.py::validate_integrated_successor_manifest` requires `mandatory_v6_adversarial_checks` to contain exactly the six required check-name strings (`REQUIRED_ADVERSARIAL_CHECKS`), but only does *set-membership* on the names — there is no digest binding to an actual test result, evidence record, or proof artifact per check, unlike every other completeness claim in this codebase (which bind via `expected_member_set_digest`/`qualification_digest` to independently-produced evidence). **Governing rule:** §5 ("do not infer PASS from... test names... comments"). **Bypass:** an evidence author writes the six literal strings into the manifest with no adversarial test having actually run. **Narrow fix:** require each check name to bind to a `check_evidence_digest` pointing at an executed, independently-witnessed proof record, the same pattern used everywhere else in this codebase.

**E. High/Medium/Low**

- **High:** the `v24_v6_decision_apply.py` / material-surface / effect-ledger "currentness" fields (`currentness_result == CURRENT`, `independence_state == QUALIFIED`) are trusted as caller-supplied booleans throughout the codebase — this candidate is a pure validation layer with no I/O; it correctly rejects internally-inconsistent or self-attested records, but genuine real-world currentness depends entirely on an external integration (not in this package) populating these fields honestly from live observations. Not a bug per se — every module says so explicitly ("does not grant runtime... authority") — but it means "QUALIFIED" from this candidate alone is never sufficient; it's necessary-but-not-sufficient by design.
